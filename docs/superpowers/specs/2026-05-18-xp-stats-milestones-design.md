# BibleVerse v2.0 — XP, Статистика, Віхи, Новий режим гри

## Загальне

Оновлення перетворює BibleVerse з простого тренажера на гейміфіковану систему з очками досвіду (XP), серією днів (стріком), підказками, новим режимом гри та повністю переробленим екраном статистики з графіком активності та віхами (milestones).

---

## 1. Система XP (очки досвіду)

### Що це
Гравець отримує XP за кожне успішне проходження вірша. Кількість залежить від складності режиму.

### Нарахування

| Режим | Складність | XP за успіх |
|-------|-----------|-------------|
| Складання слів | Легко | +30 XP |
| Заповни пропуски | Середньо | +45 XP |
| Продовж вірш | Складно | +60 XP |

### Правила
- XP нараховується **тільки при успішному** проходженні (accuracy >= поріг)
- Поріг успіху: word-order — 100%, fill-gaps — 80%, continue — 80%
- При невдачі — 0 XP
- XP **ніколи не йде в мінус** (крім підказок, де мінімум = 0)

### Відображення
- **Хедер** (біля іконки профілю): замість іконки вогню + streak — показується `🔥 {XP}` як загальний XP
- **Результат гри**: після перемоги — анімований `+30 XP` / `+45 XP` / `+60 XP`
- **Картки режимів**: під назвою — `Легко · +30 XP`

### Збереження
- localStorage: ключ `bvg_xp` (число)
- Firestore: `users/{uid}/metadata/stats.xp` (для авторизованих)
- Синхронізація: при логіні — беремо більше значення (local vs cloud)

## 2. Стрік (серія днів)

### Нова логіка
Замість серії успішних спроб підряд — серія **днів** підряд.

**Як рахується:**
1. Пройшов хоча б 1 вірш за день → день зараховується
2. Наступного дня пройшов ще → стрік +1
3. Пропустив день → стрік скидається до 0

**Заморожений день (freeze):**
- 1 раз на 7 днів автоматично закриває пропуск
- Якщо гравець пропустив **рівно 1 день** і не використовував freeze протягом останніх 7 днів — стрік зберігається
- Freeze використовується автоматично (не потрібно натискати)
- Після використання — наступний freeze доступний через 7 днів

### Дані для збереження

| Поле | Тип | Де зберігається |
|------|-----|-----------------|
| `streak` | number | localStorage `bvg_streak` + Firestore |
| `bestStreak` | number | localStorage `bvg_best_streak` + Firestore |
| `lastActiveDate` | string (YYYY-MM-DD) | localStorage `bvg_last_active_date` + Firestore |
| `lastFreezeDate` | string (YYYY-MM-DD) | localStorage `bvg_last_freeze_date` + Firestore |

### Алгоритм оновлення (при успішному проходженні вірша)

```
today = сьогоднішня дата (YYYY-MM-DD)
yesterday = вчорашня дата

ЯКЩО lastActiveDate == today:
  → нічого не робити (вже зараховано)

ЯКЩО lastActiveDate == yesterday:
  → streak++ (послідовний день)

ЯКЩО пропущено рівно 1 день І freeze не використано 7+ днів:
  → streak++ (freeze закрив пропуск)
  → lastFreezeDate = today

ІНАКШЕ:
  → streak = 1 (скинути, але сьогодні рахується)

lastActiveDate = today
ЯКЩО streak > bestStreak → bestStreak = streak
```

## 3. Підказки (Hints)

### Що робить
Підсвічує наступне правильне слово в банку слів на 1.5 секунди.

### Доступність
- **Тільки в режимі "Складання слів"** (word-order)
- Максимум **3 підказки на вірш**
- Вартість: **−5 XP** за кожне натискання
- Якщо XP < 5 — підказка недоступна (тост "Недостатньо XP")
- Стрік **не скидається** при використанні підказки

### UI
- Кнопка під ігровою зоною: `💡 Підказка −5 XP (3)`
- Лічильник залишку: `(3)` → `(2)` → `(1)` → `(0)`
- При 0 підказок — кнопка стає неактивною (disabled)
- Підсвічене слово: рамка accent кольору з пульсуючою анімацією 1.5с

### Логіка підсвічування
1. Визначити, яке слово наступне (за індексом вже розміщених слів)
2. Знайти відповідний чіп у банку (перший непересічний з правильним текстом)
3. Додати клас `hint-highlight` на 1.5с
4. Через 1.5с — прибрати клас

## 4. Новий режим гри: "Продовж вірш" (continue)

### Опис
Дається перша половина вірша. Гравець повинен дописати решту самотужки з клавіатури.

### Механіка
1. Вірш розбивається на слова
2. Перша ~50% слів показується як готовий текст (не редагується)
3. Під ними — textarea для введення другої половини
4. Кнопка "Перевірити"

### Перевірка
- Порівняння слово за словом (normalize: lowercase, без пунктуації)
- Поріг успіху: **80%** правильних слів
- Результат: відсоток правильності + правильний текст при помилці

### XP: +60 (найскладніший режим)

### Заміна
Режим **"Перші букви" (first-letters) видаляється**. Залишається 3 режими:
1. Складання слів (word-order) — легко, +30 XP
2. Заповни пропуски (fill-gaps) — середньо, +45 XP  
3. Продовж вірш (continue) — складно, +60 XP

## 7. Екран статистики — повний редизайн

### Секція 1: Стрік-картка (hero)

Градієнтна картка (такий же градієнт як progress card) з:
- Великий номер стріка: `14` (5rem, bold)
- Слово: `днів` (serif, italic, 2.5rem)
- Підпис: `підряд · продовжуй.` (0.85rem, semi-transparent)

Якщо стрік = 0: показати `0 днів` + `починай серію!`

### Секція 2: Три колонки статистики

Горизонтальний ряд з трьох блоків, розділених вертикальними лініями:

| Колонка | Лейбл | Значення | Одиниця |
|---------|-------|----------|---------|
| 1 | вивчено | {learned} | віршів |
| 2 | точність | {accuracy} | % |
| 3 | час | {minutes} | хв{seconds}с |

- Лейбл: маленький, uppercase, muted
- Значення: великий (2.8rem), bold
- Одиниця: serif italic, muted

**Час**: сума `duration` з усіх спроб. Формат:
- < 1 хв: `{секунди} с`
- 1-59 хв: `{хвилини} хв{секунди}с`
- 60+ хв: `{години} год`

### Секція 3: Графік активності (14 днів)

- Заголовок: `АКТИВНІСТЬ · 14 ДНІВ` (mono, muted, tracking)
- 14 вертикальних стовпчиків
- Висота пропорційна кількості спроб за день
- Колір стовпчиків: `var(--border-strong)` (світло-сірий)
- Сьогоднішній стовпчик: `var(--text)` (чорний/темний)
- Мінімальна висота: 4% (щоб дні з 0 спроб мали видиму полосу)
- Підписи під графіком: дата початку (30 СІЧ), середина (06 ЛЮТ), `СЬОГОДНІ`

### Секція 4: Віхи (Milestones)

- Заголовок: `ВІХИ · MILESTONES` (mono, muted)
- Список віх у форматі mode-card (іконка + текст + галочка)

**Визначені віхи:**

| Віха | Іконка | Умова | Прогрес |
|------|--------|-------|---------|
| Тиждень підряд | 🔥 (filled circle) | bestStreak >= 7 | `{streak} з 7 днів` |
| Перші 50 віршів | ⭐ (outline circle) | learned >= 50 | `{learned} з 50 завершено` |
| Псалмоспівець | ✦ (outline circle) | psalms learned >= 100 | `{count} зі 100 псалмів` |

**Стан іконки:**
- Не виконано: outline circle, muted icon
- Виконано: filled circle (dark bg, light icon), `Виконано · {дата}` + галочка справа

**Псалмоспівець — підрахунок:**
Фільтрувати verses де `book` містить "Псал" або "Psalm", порахувати скільки з них мають accuracy >= 80% за останні 5 спроб.

## 8. Відстеження часу (Time Tracking)

### Нове поле
Додати `duration?: number` (секунди) до інтерфейсу `Attempt`.

### Логіка
- `Game.start()` → зберегти `_startTime = Date.now()`
- `Game._recordAndShow()` → `duration = Math.round((Date.now() - _startTime) / 1000)`
- Передати `duration` в `Stats.record()`

### Збереження
- IndexedDB: поле `duration` в об'єкті attempt
- Firestore: додаткове поле в документі attempt
- Старі записи без `duration` — рахуються як 0

### Відображення
- На екрані статистики: сума всіх `duration` → форматування як хвилини/секунди

## 9. Acid тема — стилі для нової статистики

Кожен компонент статистики має Acid override:

| Компонент | Editorial | Acid |
|-----------|-----------|------|
| Стрік-картка | Gradient (рожево-оранжевий) | `var(--primary)` фон, `var(--primary-ink)` текст |
| Стрік-число | serif | `var(--font-display)`, uppercase |
| 3 колонки | borders `var(--border)` | borders `var(--border)` |
| Числа колонок | default font | `var(--font-display)` |
| Графік — стовпчики | `var(--border-strong)` | `var(--border)` |
| Графік — сьогодні | `var(--text)` | `var(--primary)` |
| Віхи — виконана іконка | dark bg | `var(--primary)` bg |
| Borders | `var(--border)` | `var(--border)` |

## 10. Анімація XP в результатах гри

### При успіху
Після банера результату показати:
```
+30 XP
```
Анімація: scale(0) → scale(1) з bounce (cubic-bezier 0.34, 1.56, 0.64, 1), 0.5с

Колір: `var(--accent)`

### При невдачі
Нічого не показувати (0 XP нараховано).

## Сумісність

- Старі записи `Attempt` без `duration` — працюють як 0
- Старий стрік (consecutive success) — скидається, рахування починається заново по дням
- XP починається з 0 для всіх (нова механіка)
- Firestore схема — зворотно сумісна (нові поля додаються, старі не видаляються)
